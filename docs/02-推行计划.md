## 1. 目标与成功标准

### 1.1 项目一句话

上传设备固件，云端跑成“影子设备”实测，输出**能不能进网**（三态判定 + 置信度 + 风险敞口）、**进来放行什么**（可验证、可回滚的最小权限策略）、**同族还有多少同类问题**。

### 1.2 初赛成功标准（不是做完系统）

| # | 标准 | 判定 |
|---|---|---|
| S1 | 信息收集表提交 | 11/30 前提交，命名“学校-队名-队长姓名-手机号” |
| S2 | 初赛材料齐全 | 设计方案 + PPT + 演示视频，覆盖五个必含项 |
| S3 | 五个必含项都有硬内容 | 背景价值 / 创新性 / 数据集与处理 / 关键代码片段 / 可量化指标 |
| S4 | 华为技术留痕 | CodeArts 截图 ≥6 张、commit ≥6 条带 `[codearts]`、RDS/Redis 方案说明 |
| S5 | 材料可复现 | 代码能跑、命令写清、数据来源可查 |

### 1.3 评分对齐（官方权重）

- **创新性 60%**：证据分级决策、策略合成+回滚、“微隔离要上线才能学、我们上线前就给策略”
- **应用价值 40%**：校园/园区网管真实场景、等保最小授权、可复制性

## 4. 初赛材料生产流水线

```
真实实验数据 ──→ materials/实验记录.md ──→ 指标表
      │                                  │
      ├──→ 代码片段 ──→ 代码片段解读 ────┤
      │                                  ▼
      └──→ 数据集说明 ─────────────→ 信息表草稿 → Word 正式版
                                         │
                                         ├→ PPT大纲 → PPT 正式版
                                         └→ 视频脚本 → 视频成片
```

**顺序不能反**：先有实验记录，再有指标，最后写材料。**没有数据的章节不写。**

## 5. 质量门（Definition of Done）

一个任务算完成，必须同时满足：

1. 代码在 `src/`，测试在 `tests/`，`python -m pytest -q` 全绿；
2. 有至少 2 个用例，其中一个覆盖失败路径；
3. 输出样例落盘到 `materials/`，不是只在对话里；
4. 没有新增未说明的依赖；
5. commit 信息为 `[codearts] <scope>: <what>`；
6. 在 `materials/实验记录.md` 追加一行（日期/任务/结果/阻塞）。
