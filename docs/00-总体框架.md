## 2. 项目定位（一句话 + 三条结论）

> 上传设备固件，云端跑成“影子设备”打一遍，给出**能不能进网**（带置信度与风险敞口）、**进来放行什么**（可验证、可回滚的最小权限策略）、**同族还有多少同类问题**。

三条结论：
1. **决策**：三态判定（通过 / 有条件 / 拒绝）+ 置信度 + 风险敞口 + 证据清单；
2. **策略**：从影子设备实际流量合成最小权限策略，下发 → 回放 → 回滚；
3. **影响面**：按谱系外推到同族型号（本期人工聚类）。

**与现有方案的结构性差异**：微隔离要“先上线才能学”，准入发生在“上线之前”；影子设备让“尚未部署的设备”也能产生流量与证据。

### 4.1 必做（初赛材料需要）

| # | 交付物 | 验收 |

| 6 | **关键代码片段** 2–3 段 | 解包、敞口计算、策略生成 |
| 7 | **PPT + 3 分钟视频** | 按初赛模板 |
| 8 | **信息收集表** | 11/30 前提交 |

### 4.2 初赛不做（写进“总决赛计划”）

完整 Web 控制台、云上部署、多租户、自动化谱系、批量调度、继电器/硬件控制、商业计划书。

> 依据：初赛评分只看材料（创新 60% + 价值 40%），不看线上 Demo。**把力气花在材料能看见的地方。**

## 7. 初赛材料 ↔ 评分项对照

| 评分项（权重） | 材料位置 | 必须出现的东西 |
|---|---|---|
| 创新性（60%） | 第 3 节 + 3.4/3.5 | “证据分级决策”“策略合成+回滚”“微隔离要先上线、我们上线前就给策略” |
| 应用价值（40%） | 第 1 节 + 场景 | 校园/园区网管、等保最小授权、可复制性 |
| 数据集与处理 | 第 7.1 | 12 个固件来源、锚点清单、标注口径、公开/自有比例 |
| 关键代码片段 | 第 7.2 | 解包封装、敞口公式、策略生成各一段 |
| 可量化指标 | 第 7.3 | 判定一致性、锚点正确率（≥3）、误杀/漏放、策略条数 |

### 7.1 数据
- 固件：12 个（摄像头 6 / 路由 6），来源与许可逐条记录；
- 锚点：Tenda O4 V3.0（已有）+ 2 个待补；
- 标注：2 人独立标 12 固件 × 4 类风险，分歧仲裁。

### 7.2 代码片段（初赛只放这 3 段）
1. `unpack.py`：binwalk 封装 + 文件系统定位；
2. `exposure.py`：`U = [Σ未覆盖 w + Σ(E2/E3) w·(1−c)] / Σw`；
3. `policy.py`：端点 → 粒度选择（FQDN / vendor-group / ASN）→ ACL/MUD。

### 7.3 指标
- 判定一致率（全标注集）+ 判定正确率（仅锚点，≥3 才算）；
- 误杀率 / 漏放率（策略回放）；
- `asn-fallback` 占比；
- 端点意图分类 F1（若做，规则 vs 模型+规则，McNemar）。

## 8. CodeArts 码道使用规范

### 8.1 形态选择（2026-11-19 定）
- **主用：码道 IDE**（独立 AI IDE，功能更全，用户已倾向此形态）；
- 备选：VSCode 插件 `huaweicloud.vscode-codebot`（已装已登录，适合临时改一处代码）；
- 两者都能满足赛题“使用 CodeArts 代码智能体”的要求，**但只能选一个作为留痕主线**，避免对话记录分散；
- `codearts` CLI 尚未安装（`codearts` 命令不存在），装上后才可由 DSH 通过 `codearts run` 触发。

### 8.2 正确用法（6 步）
1. **打开项目**：IDE 里打开 `E:\dsh_talking\firmware-admission`（不打开文件夹，聊天里的改动不会落盘）；
2. **开通服务**：developer.huaweicloud.com/codeartsco 开通体验版，确认已实名、余额充足；
3. **选模式与模型**：智能体模式；批量/脚手架用低价模型（如 GLM-5.3-Flash），难题用强模型（如 DeepSeek-V4.1 或 Kimi-K3.1-Pro），**每次记录用了哪个模型**；
4. **开权限**：读取文件、编辑文件、执行命令、MCP、待办、浏览器；
5. **配项目规则**：在仓库 `.codeartsdoer/rules/` 写死“只改 src/、禁止改 docs/、提交前跑 pytest”；
6. **任务卡驱动**：每次给“输入 / 输出 / 验收标准”，不让它自由发挥。

### 8.3 三个提示词模板
- 脚手架：`在 src/ 下实现 firmware unpack 封装，输入 .bin，输出文件系统路径与组件清单；不要改 docs/；附 pytest。`
- 模块：`实现 exposure.py：输入检查项覆盖与证据等级，输出 U 值；按 3.4.1 公式；写 3 个单测。`
- 文档：`把 docs/ 下的实验记录整理成“数据集与处理”一节，800 字，保留数字与出处。`

### 8.4 MCP（可选，加分）
- CodeArts 是 **MCP 客户端**：可在 `.codeartsdoer/codearts_cli.jsonc` 配 `huawei-cloud-mcp`（封装 KooCLI），让它“查 RDS/ECS 资源”而不是猜；
- 配置后执行 `/mcps` 验证；远程模式用 URL，本地模式用 command。

### 8.5 留痕（资格红线）
每次生成保留：对话截图、commit message 标注 `[codearts]`、生成前后的 diff。材料里单列“开发过程”一页。

## 9. 协作方式：DSH 与 CodeArts 怎么配合

| 方案 | 可行性 | 做法 |
|---|---|---|
| A. 共享仓库（今天可用） | ✅ | CodeArts 在 VSCode 改 `src/`；DSH 在同一目录 review、跑测试、写 `docs/` |
| B. DSH 调 CLI（需装） | ⚠️ 待验证 | 安装 `codearts` CLI 后，DSH 执行 `codearts run "任务"`；需把权限设为 allow，且沙箱放行网络 |
| C. MCP 反向调用 | ❌ 目前不行 | CodeArts 只做 MCP 客户端，不暴露 MCP 服务端；DSH 无法通过 MCP 直接驱动它 |

**边界**：DSH 不能装进 VSCode（它是独立运行时，有自己的 Web GUI）。可行的是“共享文件系统 + 任务卡 + （可选）CLI 触发”。
