## 1. 部署拓扑与职责划分

```
                        ┌──────────────── ECS（Docker）────────────────┐
                        │  控制台 Web  ──  API 服务  ──  报告服务        │
                        └───────────┬─────────────────┬───────────────┘
                                    │                 │
                        ┌───────────▼──────┐  ┌───────▼────────┐
                        │ RDS MySQL 8.0     │  │ Redis 主备      │
                        │ 固件/证据/判定/策略│  │ 任务队列/解包缓存│
                        └───────────────────┘  └───────┬────────┘
                                                       │ 任务拉取
                        ┌──────────────────────────────▼─────────────┐
                        │ 仿真 Worker（FirmAE / QEMU / binwalk）      │
                        │ ★ 只在本地运行，不上云（见 §5）              │
                        └────────────────────────────────────────────┘
```

职责边界：

| 组件 | 位置 | 承载内容 | 是否上云 |
| --- | --- | --- | --- |
| RDS MySQL 8.0 | 华为云 | 六张业务表（见 `materials/rds_schema.sql`） | 是 |
| Redis | 华为云 | 解包/仿真任务的队列与幂等键 | 是 |
| ECS + Docker | 华为云 | 控制台 Web、API 服务、报告与策略生成 | 是 |
| 仿真 Worker | 本地 Linux 主机 | FirmAE + QEMU + binwalk，产出证据 JSON | **否** |

> 依据 `docs/00-总体框架.md` §5：RDS 存固件/证据/策略/锚点，Redis 做仿真任务队列与解包缓存，部署在 ECS；QEMU 依赖硬件虚拟化与内核模块，云端容器无法保证，故 Worker 留在本地。

## 2. 资源清单（规格为选择，非实测）

| 资源 | 选择 | 理由 |
| --- | --- | --- |
| RDS for MySQL | 8.0 版本、单机版、通用型小规格 | 数据量在万行以内，单机足够；8.0.16+ 才强制生效 `CHECK` 约束（本脚本依赖） |
| RDS 存储 | 按最小规格起步 | 固件本体不入库（只存 URL 与 SHA-256），库内只存元数据与证据文本 |
| Redis | 主备版、最小内存规格 | 队列与任务状态，允许丢失重跑与缓存命中，不需要集群 |
| ECS | 通用型、Linux（Ubuntu 22.04 或 Huawei Cloud EulerOS） | 只跑 Docker 容器，无 GPU/大内存需求 |
| 对象存储 | OBS（可选） | 存报告与解包日志，对应 `unpack_job.log_ref`；初赛可先用本地路径 |

- 具体规格数值（vCPU/内存/存储 GB）以代金券可用规格为准，签约前确认：`TODO(measure) 实际可用规格`。
- 部署耗时、镜像构建耗时、首次启动耗时：`TODO(measure)`。

## 3. 云服务开通步骤（必须由 CodeArts Skills 完成）

赛题任务要求第 2 条明确"基于已有智能体和 Skills，进行关联 RDS、Redis 等云服务的快速开通创建"。因此开通动作**不得手工点控台**，全部在华为云码道会话内通过 Skill 完成，并逐步截图留痕。

### 3.1 RDS for MySQL 开通

1. 打开码道 IDE，进入本项目工作区，确认已登录华为云账号并具备 RDS 购买权限。
2. 在码道对话中调用华为云资源类 Skill，指令示例：
   `开通 RDS for MySQL 8.0，单机版，最小规格，与 ECS 同 VPC，私有子网，自动备份 7 天，库名 firmware_admission`
3. 核对 Skill 返回的确认信息：引擎版本、规格、VPC/子网、端口 `3306`、备份策略、计费方式。
4. 确认开通，等待实例状态变为"运行中"，记录**内网地址**（不要开公网地址）。
5. 建库 `firmware_admission`（字符集 `utf8mb4`），账号只授予该库的 DML/DDL 权限，禁止使用 root 账号连接应用。
6. 按 §4 执行 `materials/rds_schema.sql`。

### 3.2 Redis 开通

1. 在同一码道会话内调用 Skill：
   `开通 Redis 主备版，最小内存规格，与 ECS 同 VPC 私有子网，密码认证开启`
2. 核对返回信息：实例类型、规格、内网地址、端口（默认 `6379`）、密码认证、最大连接数。
3. 确认开通，记录**内网地址与端口**；关闭公网访问。
4. 应用侧连接串通过环境变量注入（见 §6），不写入镜像与仓库。

### 3.3 开通动作的留痕要求

- 每次 Skill 调用必须截取：**对话中的 Skill 指令原文 + 返回的实例确认信息**，且能看清底部模型名。
- 截图按 `materials/codearts/截图索引.md` 的命名规则编号入表（见 §7）。

## 4. 建表与初始化

1. 在 RDS 控制台（或 Skill 提供的 SQL 执行入口）切换到 `firmware_admission` 库。
2. 执行 `materials/rds_schema.sql`（全部 `CREATE TABLE IF NOT EXISTS`，可重复执行）。
3. 校验：`SHOW TABLES;` 应返回 `firmware`、`evidence`、`decision`、`policy`、`anchor`、`unpack_job` 六张表。
4. 校验 CHECK 生效：MySQL 8.0.16 以下会静默忽略 `CHECK`，须确认版本；否则置信度/敞口越界只能由应用层（`src/schema.py`）兜底。
5. 锚点初始化：按 `configs/anchors.yaml` 逐条 INSERT 到 `anchor` 表，`verified=1` 的锚点必须带真实下载链接与具体版本。

## 5. 仿真 Worker 只在本地（不上云）

**结论：FirmAE / QEMU 仿真 Worker 只在本地运行，不放入云上容器，也不部署到 ECS。**

理由：

1. FirmAE 依赖 QEMU 全系统仿真 + KVM 硬件虚拟化，容器内嵌套虚拟化不可靠，云主机规格默认不保证；
2. 仿真过程需要 root 级网络栈操作（TAP 设备、网桥、iptables 规则），与云主机安全组策略冲突；
3. 未知固件必须在隔离环境运行，本地专用主机便于随时整机快照回滚；
4. 赛题材料本身按"证据来自隔离仿真环境"表述（`configs/judgement.yaml` §wording），把 Worker 放云上只会放大风险而不增加评分。

落地方式：Worker 通过 Redis 队列拉取任务，产出证据 JSON 后经 API 回传 RDS；Worker 与云上之间只走 HTTPS + 队列，不开放入站端口。

## 6. ECS + Docker 部署步骤

1. **准备主机**：ECS 选择同 VPC 私有子网，绑定弹性公网 IP 仅用于运维；安装 Docker Engine 与 Compose 插件（版本 `TODO(measure) 实际安装版本`）。
2. **拉取代码**：`git clone` 本仓库到 `/opt/firmware-admission`（初赛阶段仓库尚未开源，可先上传压缩包）。
3. **准备环境变量**：在 `/opt/firmware-admission/.env`（权限 `600`，不入库）写入：
   - `RDS_HOST` / `RDS_PORT=3306` / `RDS_DB=firmware_admission` / `RDS_USER` / `RDS_PASSWORD`
   - `REDIS_HOST` / `REDIS_PORT=6379` / `REDIS_PASSWORD`
   - `APP_PORT`（应用监听端口，`TODO(measure) 待 src/api 定稿确认`）
4. **构建镜像**：编写 `Dockerfile`（基础镜像 `python:3.14-slim`，与开发解释器 3.14.7 对齐；复制 `src/`、`configs/`、`requirements.txt`，`pip install -r requirements.txt`），执行 `docker build -t firmware-admission:latest .`。
   > `requirements.txt` 已存在（运行时 `pyyaml`、开发 `pytest`）；当前 `src/` 只含 `schema.py` / `config.py`，`Dockerfile` 与服务入口在对应任务卡完成后补齐（见 `TODO(measure)` 清单）。
5. **启动**：`docker compose up -d`（单容器即可；控制台与 API 同容器不同进程，或按需拆两个服务）。
6. **自检**：
   - `docker compose ps` 全部 `running`；
   - 应用 `GET /healthz` 返回 200（接口由 `src/api` 提供，尚未实现，`TODO(measure)`）；
   - 从容器内 `mysql -h $RDS_HOST -u $RDS_USER -p` 与 `redis-cli -h $REDIS_HOST` 连通成功。
7. **日志与重跑**：`docker compose logs -f`；镜像升级用 `docker compose pull && docker compose up -d`，异常回滚到上一个 tag。

## 7. 安全组最小开放

原则：公网只放业务端口，数据库与缓存永不开公网，管理端口按来源 IP 收敛。

| 安全组 | 方向 | 协议/端口 | 来源/目标 | 说明 |
| --- | --- | --- | --- | --- |
| ECS-SG | 入站 | TCP 443（或 `APP_PORT`） | `0.0.0.0/0` | 对外服务唯一入口 |
| ECS-SG | 入站 | TCP 22 | 仅管理员固定公网 IP `/32` | SSH 运维，禁止全网开放 |
| ECS-SG | 入站 | 全部 | `0.0.0.0/0` | **拒绝（默认）** |
| ECS-SG | 出站 | TCP 3306 | RDS-SG（内网地址） | 访问数据库 |
| ECS-SG | 出站 | TCP 6379 | Redis-SG（内网地址） | 访问缓存 |
| RDS-SG | 入站 | TCP 3306 | ECS-SG | 仅 ECS 可连，不开公网 |
| Redis-SG | 入站 | TCP 6379 | ECS-SG | 仅 ECS 可连，不开公网 |

补充要求：

- RDS / Redis 均**不开公网地址**，只保留内网地址；
- 数据库账号最小权限，禁止 root；Redis 必须开启密码认证；
- 密钥、连接串只放 `.env` 或环境变量，禁止提交到仓库（`00-project.md` 安全约束）。
